# 数学手册(原书第10版) 20.2.9 程序设计

本页对应《数学手册（原书第10版）》20.2「Mathematica 的重要结构要素」的第 9 小节「程序设计」，主题为 [[entities/mathematica]] 的程序设计构造：循环结构（`Do`、`While`）、局部变元（`Module`）与函数式程序设计方法（`Nest`、`NestWhile`、`Apply`、`Map`、`MapThread`、`Distribute` 等运算）。在 wiki 已入库序列中，本节上承 20.2.6「函数」（[[sources/10-数学手册原书第10版--7-2026-函数--v9sqy0]]），隶属父节 [[sources/10-数学手册原书第10版--22-202-mathematica的重要结构要素--1w5xyrj]]；注意 20.2.7、20.2.8 未见入库记录（[[queries/20-2-9未入库回指缺口]]）。

## 内容结构

小节依次介绍三层程序设计构造：

1. **循环结构**：`Do`（定次数）与 `While`（条件驱动）两个基本命令，见 [[concepts/Do与While循环]]；
2. **局部变元**：`Module` 命令及其作用域语义，见 [[concepts/Module与局部变元]]；
3. **函数式程序设计**：经 `Nest`、`NestWhile`、`Apply`、`Map`、`MapThread`、`Distribute` 等运算实现的方法，原文称其为 Mathematica 程序设计功能的「真正力量」所在，见 [[concepts/Mathematica函数式程序设计]]。

## 构造与算例（结构化转录）

以下代码为原文逐字转录，仅将 OCR 产生的字体空格噪声（如 `\mathsf {D o}`）规整为标准 Mathematica 记法。

循环结构（式 20.24a/b）：

```
Do[expr, {i, i1, i2, di}]
While[test, expr]
```

原文语义说明（该句存在脱字，见下文「转写讹误」）：`Do` 对表达式 expr 重复求值，循环变量 i 以步长 di 从 i1 取值到 i2；略去 di 则步长为 1；再略去 i1 则从 1 开始。`While` 只要 test 具有值 True 即持续对 expr 求值。

e² 级数近似算例（式 20.25）：

```
In[1] := sum = 1.0;
        Do[sum = sum + (2^i/i!), {i, 1, 10}];
        sum
Out[1] = 7.38899
```

局部变元命令（式 20.26）：

```
Module[{t1, t2, ...}, procedure]
```

例 A：整数平方根之和的过程式程序（式 20.27）：

```
In[1] := sumq[n_] :=
         Module[{sum = 1.},
           Do[sum = sum + N[Sqrt[i]], {i, 2, n}];
           sum];
```

调用 `sumq[30]` 得到的结果是 112.083。

例 B：函数式改写（原文无编号公式）：

```
sumq[n_] := N[Apply[Plus, Table[Sqrt[i], {i, 1, n}]], 10]
```

`sumq[30]` 的结果是 112.0828452。原文又称 `Total[Sqrt[N[Range[n], 10]]]` 给出相同的结果，而「不使用下标，不连续递增其值，也无须变元 sum 及其初始值」。

末句：「详细情况见 [20.16]」，该文献编号在摘录内不可考。

## 主要论点

- **论点 1（循环语义）**：`Do` 为定次数循环、`While` 为条件驱动循环；`Do` 的步长默认为 1、起点默认为 1。证据为式 20.24a/b 及文字说明，与 Mathematica 实际语义一致（[[findings/式20-24与20-26循环与模块语法转录复算]]）。
- **论点 2（作用域）**：`Module` 变元列表中的变元或常数在模块内局部可用，模块内指派的值在模块外无效。证据为式 20.26 与例 A。
- **论点 3–5（算例数值）**：式 20.25 之 7.38899、例 A 之 112.083、例 B 之 112.0828452 均经独立复算验证通过，分别见 [[findings/式20-25-e2级数近似算例复算]]、[[findings/式20-27-sumq过程式算例复算]]、[[findings/例B-函数式sumq与Total复算]]（其中 `Total` 变体的逐位一致性未经实测，属推断）。
- **论点 6（作者观点，修辞性）**：函数式方法是 Mathematica 程序设计「真正力量」所在，优于下标递增的过程式写法。无量化证据，但例 A/B 对比为其提供佐证（[[comparisons/过程式与函数式sumq实现比较]]）。
